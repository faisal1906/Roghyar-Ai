## Photo-feature and privacy findings

- No symptom-photo plumbing was found to remove. The only committed image assets under the app are the 192px and 512px PWA icons. SVG interface icons and microphone speech capture remain legitimate. The PDF and historical references are preserved.
- `phase1.spec.ts` uses the production build to check file and capture controls, camera/video and image-preview surfaces, no automatic device access, no assessment traffic or draft logging, and safe text-only review and emergency help offline. Existing regression suites continue to cover microphone permission and cleanup, duration cases, keyboard and axe checks, public caching, and update safety.
- `test_phase1_policy.py` inventories FastAPI and OpenAPI routes, request bodies, model fields, direct backend dependencies and Alembic revisions. An upload-shaped synthetic request to the assessment boundary returns 404 without echoing or logging the marker. Clinical settings tests independently reject activation.
- `test_postgis.py` inventories all application-owned table and view columns after migration. The Alembic version relation is the only application-owned table. Extension-owned geometry tables and views are outside that inventory. `photo-policy.test.mjs` inventories frontend build dependencies and production lockfile packages.
- Review future route, request field, dependency and migration additions before updating the inventories. Inspect code paths, optional/indirect dependencies and uploaded/build assets manually. The guards check present capabilities and known browser paths. They do not analyze arbitrary code for concealed processing.
- The source review found only the same-origin liveness request and operational readiness logs. No client credentials or active analytics, clinical analysis, medicines, directory fixtures or booking data were found. CI covers no storage of drafts and no unauthorized location or camera access. Later server collection requires its own security and privacy review.

## Verification and performance evidence

The [UI-06 pull request checks](https://github.com/faisal1906/Roghyar-Ai/pull/6/checks) track the hosted suite for this branch. The [UI-05 run](https://github.com/faisal1906/Roghyar-Ai/actions/runs/44566818738) is the successful pre-audit baseline with 11 frontend unit tests, 40 Chromium tests and 14 backend tests including PostGIS.

The [successful UI-06 hosted run](https://github.com/faisal1906/Roghyar-Ai/actions/runs/44570578763) tested commit `6abfdce5c1d61bf030dfd0f10114cbdd10988910`. It passed **12 frontend unit tests, 42 Chromium tests including axe, and 17 backend tests with zero skips**. It also passed TypeScript, the production PWA build, OpenAPI and generated client drift checks, and Alembic upgrade → downgrade → upgrade on live PostGIS. The schema inventory reported only the Alembic version relation at both head checks. Manual emergency opening measured 25.6ms in hosted Chromium.

Local UI-06 verification passed 12 frontend unit tests, 42 Chromium tests including the axe scans, and 16 backend tests with live PostGIS reserved for hosted CI. TypeScript, production build, OpenAPI regeneration and generated TypeScript checks passed. The UI-06 local manual emergency opening sample was 24.8ms.

Installed Windows Chrome 155.0.8059.80 and Edge 155.0.4283.45 passed automated headless smoke checks on the production preview. Both connected to the real health service, retained the editable draft across routes, and showed both telephone links after an offline reload. This check used no physical calls or recorded speech.

Five Windows Chromium samples per production build used a 360×640 viewport, 4× CPU throttling, 80ms simulated latency and 200,000 bytes/s download. UI-05 → final UI-06 median cold first/largest contentful paint was 1,496 → 1,672ms, and median offline first paint was 248 → 316ms. Both sampled builds recorded zero layout shift and two startup app-asset requests. UI-06 recorded three to four long tasks per run. Gzipped JS/CSS was 69.59/3.98kB. This is a desktop simulation. Physical low-end Android performance and clinical detection latency are separate checks.

**Phase 1 engineering is complete.** The UI-06 hosted guard and all automatable acceptance checks passed. Physical-device acceptance and product release criteria stay open with the owners in the matrix. BE-01 is the next engineering ticket.
