# GD-02 reviewed structured home-care content

PDF section 6.2 distinguishes reviewed summary, ordered steps, warning statements and a time check from formulary medication. Schema v1 requires nonempty steps and warnings, one to three exact en/ur/ps variants with locale review references, and a signed optional follow-up interval of 1–720 hours. An interval means the approved time check, with no inferred interval. Strings are bounded to 600 code points, lists to eight items, and the canonical signed body to 32 KiB. Plain-text validation excludes markup delimiters, executable placeholders and unsupported Unicode controls. Unknown fields and all medication structures are excluded. Clinical review must ensure the free text stays within the non-medication category. Text validation cannot determine medical meaning or recognize all drug references.

The Ed25519 signature uses the home-care-content v1 domain and binds the complete canonical body. SHA-256 identifies those same bytes. A separately configured reviewer must hold home_care scope, match the reviewer identity, and have current unrevoked authority at lookup. The signed scope includes condition, applicability, source provenance and review/expiry times. Missing locale returns no text. There is no fallback language, transliteration or composition across versions.

The default repository is an empty immutable in-memory snapshot. There is no write or publisher interface. A snapshot can retain signed inactive history; duplicate revisions are rejected and conflicting active versions fail closed. Rollback requires a newly provisioned snapshot with a still-valid, exact signed active revision and current authority. Cross-snapshot immutable history, lifecycle transitions (draft, submitted, superseded and revoked), audit retention and atomic publication are incomplete durable-repository requirements. GD-04 and infrastructure must implement these with dedicated roles, forced RLS and immutable reviewed history. No migration or database grant is introduced here.

GD-01 first applies owner/expiry/revision checks and independent signed clinical precedence. Lower approval may bind an additional exact structured content identity, version, digest and scope, independently of the existing AI-04 signed reply. Both signatures must verify, and the selected summary must exactly equal the existing signed reply text. A missing bundle, invalid binding, outage or disagreement yields no clinical instructions. Existing GD-01 copy-only contracts retain their behavior. Structured authorization remains absent by default. Internal catalog lookup verifies content only, and callers must not use it as a patient authorization API. Nothing is cached across authority snapshots.

No patient data, medicine fields, public endpoints or release flags change. GD-03 owns medication eligibility; GD-04 owns qualified reviewer onboarding, publisher custody and translation approval. QA-01 and qualified language reviewers must validate the actual clinical content. Identity, consent, retention, atomic state custody, key operations, model evaluation and physical-device language QA remain open.

Synthetic tests use disposable keys and placeholder wording. In-memory timing samples cover schema, canonical digest, Ed25519, combined lookup/render, and empty denial. They exclude database, network and clinical latency.

GD-04 adds an optional [PostgreSQL repository](39_TRANSLATION_AND_CLINICAL_PUBLISHING.md). The original snapshot remains available for synthetic tests.
