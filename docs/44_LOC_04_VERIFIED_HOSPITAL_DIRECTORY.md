# LOC-04 verified hospital directory governance

This ticket adds a private operator workflow. Hospitals still shows directory unavailability. No patient location is sent to the backend, and no public import, review, publication or search route was created. No real provider records, source authorities, operator accounts or reviewer keys are provisioned.

## Operating sequence

1. Run `validate_batch(payload)` on a UTF-8 JSON v1 batch. It checks byte and row limits, strict shapes, duplicate keys and identities, WGS84 ranges and unsafe text without writing to the database. Coordinate order that is valid in both directions requires review against the source.
2. An importer with an individually authenticated restricted login submits the batch and private evidence bytes through `Directory.submit`. The configured source organization, opaque evidence reference, observation timestamp, source record/version and SHA-256 digest bind each candidate. Evidence documents stay in the operator's controlled store. The application verifies their bytes and persists references and digests. Store custody and retention procedures require separate approval.
3. A reviewer uses `candidate_for_review` to inspect the immutable revision, independently obtains the referenced evidence, and submits a detached Ed25519 `Review` with that evidence. The signature uses the directory-specific domain and binds identity, source digest, revision, individual value digests and expiry. Approval covers the exact collection of aliases. An omitted phone or emergency statement stays unknown. Rejected and correction-required reviews retain their immutable history.
4. A third authenticated operator invokes `publish`, `withdraw`, `withdraw_alias`, or `revoke`. Publication validates the signature and current permitted source and reviewer scope again. A scoped database trigger projects the approved fields into the existing hospital row, writes audit evidence and activates eligibility in a single transaction. Separately authorized functions report expiry or upcoming revalidation and sanitized audit entries.

Operator commands are private Python service calls using separate, non-inheriting PostgreSQL logins and externally configured login allowlists. No command falls back to application runtime or maintenance credentials. Candidate identities use UUIDs and versioned source record keys. Exact retries are idempotent. An inconsistent UUID/source linkage or nonsequential revision returns an identity conflict for manual resolution. Similar names and same-name branches are never automatically merged. Cross-source linkage requires an independently governed operator process.

## Current eligibility

LOC-02 and LOC-03 require the existing verified/published flags plus a current signed-publication projection within its expiry. Old flag-only rows remain in the schema for foreign keys and are excluded from these search services. Source and key revocations remove the current publication immediately. Alias revocation is bound to its exact hospital revision and text digest, leaving other approved aliases searchable. Corrections create new immutable candidate and review revisions. Historical publication cannot be replayed. Replacements preserve existing hospital IDs and produce withdrawal and publication audit records with a shared transaction ID. Search uses repeatable-read snapshots. A search started before a revocation can observe the prior snapshot, and a later search sees the change.

The engineering freshness ceiling is 30 days since evidence observation and may be configured lower. Signed review and credential expiry may impose shorter limits. Freshness is enforced at query time. Operations must persist key/source revocation through the private workflow for previously published records. Changing an in-memory authority registry alone does not propagate a historical revocation across processes. An unknown emergency flag is omitted as a positive or negative screening fact. Existing LOC-02 unsupported filters remain unavailable.

## Database custody and release

Migration `0009_directory_governance` adds forced-RLS history, locally scoped directory roles and narrowly privileged security-definer projection and audit functions. It removes ordinary maintenance writes to hospitals. Review and publication have different privilege boundaries. Direct credential custody, least-privileged database grants and segregation of operator service logins are release requirements. The migration refuses downgrade with retained custody history. On an empty disposable database, downgrade to `0008_hospital_autocomplete` and then re-upgrade. For operational data, retain an audited backup and obtain a separate archival and recovery approval.

Hosted evidence binds the disposable live PostgreSQL test identities, migration observations and earlier location artifacts to the exact commit. Real evidence intake, identity-conflict operations, key and source credential onboarding, alias source policy and languages, privacy/retention, representative performance and public release approval remain external. The product requirements call for a genuine reviewed directory. Synthetic fixtures verify engineering behavior and must remain disposable.
