# LOC-02 private PostGIS hospital proximity search

`HospitalSearch` accepts a private strict query with finite numeric latitude and longitude, an optional 5, 15, 30 or 60 km radius, a tri-state emergency filter, a sort mode and a limit from 1 to 50. Coordinates are omitted from the query model's representation. The result contains a stable hospital identity, public address fields, WGS84 distance, verification date and recorded emergency flag. It excludes hospital coordinates, patient coordinates and reviewer/source details.

Each radius uses `ST_DWithin` for inclusion and `ST_Distance` for reporting on spheroidal `geography(Point,4326)`. Longitude is X. PostGIS applies its inclusive distance predicate at the radius in meters, with boundary behavior subject to floating-point precision. The hosted fixtures assert inclusion and exclusion five centimeters either side of every radius and check independently expected WGS84 distances, including the antimeridian and a high-latitude crossing. This is straight-line distance. The service provides neither ETA nor road distance.

An explicit radius is searched once. Automatic mode reads 5, 15, 30 and 60 km in order and stops at the first filtered match. Eligibility, ordering and filtering remain unchanged during expansion. A window count records all qualifying rows in the selected radius before the result limit. Nearest ordering uses distance and UUID. Emergency-first adds the stored emergency flag as the primary sort key. The flag alone does not establish current emergency intake. Null filters mean no filter. Type, open-now, specialty and specialty-match sorting return an explicit unsupported result. The PDF and planned API refer to attributes without reviewed semantics in the current schema. Free-text departments do not establish a governed specialty or doctor match.

The repository uses the dedicated runtime login through `scoped_session`, a read-only anonymous repeatable-read snapshot, verification and publication predicates, and a 1.5-second statement timeout. The search distinguishes absent published directory, no matches, untrusted connection, timeout and database outage. The supplied engine must hide parameters and have SQL echo disabled. No migration or directory seed is required. A live test checks the existing GiST index and records EXPLAIN observations with default and diagnostic planner settings. Disabling sequential scans is limited to this diagnostic test. An observed plan on disposable fixtures does not predict production performance.
