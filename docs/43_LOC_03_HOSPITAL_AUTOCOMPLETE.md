# LOC-03 private hospital autocomplete

The planned `GET /hospitals/search?q=` remains closed. `HospitalAutocomplete` is an internal SQLAlchemy service with a strict Pydantic contract. It accepts up to 120 code points, requires at least three letters or numbers for queries, and limits suggestions to 1–25. City, district and province are optional exact normalized filters. Empty and malformed input, control and format characters, SQL wildcard tokens, excessive combining marks and repeated text are rejected before SQL. The service omits query fields from model representations and requires hidden SQL parameters and disabled echo.

Names and query text are normalized to NFC, trimmed, folded to one separator between words, and compared in lowercase using PostgreSQL. Exact and prefix comparisons preserve punctuation. PostgreSQL trigram tokenization can treat punctuation variants as fuzzy matches. Urdu and Pashto display spellings remain unchanged. Explicit stored aliases can cross scripts. The service generates no transliterations or aliases. Synthetic cases verify mechanics, while multilingual fuzzy quality remains unverified.

Canonical exact matches rank first, followed by exact stored aliases, canonical prefixes, alias prefixes and canonical fuzzy candidates. The fixed pg_trgm threshold is 0.45. Higher fuzzy similarity ranks above lower similarity, with UUID as the final tie-breaker. Alias joins reduce to one rank per hospital, and selection never collapses distinct hospitals with the same name. Suggestions return id, name, city, district, province, match category and the recorded verification date. That date identifies the recorded review, rather than guaranteeing current availability.

The query uses parameterized SQL, a read-only repeatable-read anonymous scope, the dedicated runtime login, unchanged forced RLS, explicit verified/published predicates and a 1.5-second statement timeout. It distinguishes invalid input, short query, no matches, unavailable directory, untrusted connection, timeout and outage. Revision `0008_hospital_autocomplete` provisions pg_trgm, a shared SQL normalization function, partial pattern and trigram indexes, and a trigger requiring withdrawal of verification before reviewed provider-data edits. Stored data and historic approval metadata remain in place. Real provenance and fresh publication review remain LOC-04 responsibilities.

Hosted plans are recorded under the restricted role for common, uncommon and fuzzy terms over 800 additional disposable names. Each is a single synthetic observation. On the initial hosted disposable run, the restricted planner selected neither index for any of the three queries. A separate owner-only diagnostic discourages sequential scans to test whether the query shape permits index paths. It is recorded separately from the normal runtime plan. No production planner settings or RLS permissions were changed. Alias lookup currently examines stored alias arrays within the eligible scope. Result limits, the minimum query length and a transaction-local timeout bound service work. Production-scale query performance needs representative evidence before public activation.

Hospitals continues to display directory unavailability, with LOC-01 fixes remaining in local memory. Public activation requires independently verified data, a freshness and withdrawal workflow, throttling and abuse controls, request-id and safe error behavior, a no-store policy and a review of term logging and retention, including future GET URLs and database parameter settings. No frontend discovery, maps, coordinates or external autocomplete service is integrated.
