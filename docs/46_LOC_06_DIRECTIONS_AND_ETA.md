# LOC-06 private directions and optional ETA

The PDF describes provider road routing and optional traffic integration once available. LOC-06 has no approved live provider or user location disclosure. The Hospitals page retains directory unavailability, presents a text-only directions fallback and leaves manual Rescue 1122 accessible offline. No public API, maps widget, schema migration, or booking workflow is introduced.

The private destination repository uses the anonymous restricted runtime in a read-only repeatable-read transaction. It resolves the exact current LOC-04 hospital UUID and revision. A supplied doctor needs an eligible LOC-05 affiliation for that same facility and current specialty authority. The point is the reviewed facility map position. Validated entrances, ambulance routes, road closures and operational facility availability are outside this contract. Search-time snapshots do not confer authorization. New routing requests read again, and results recheck the destination after provider I/O. Expired, withdrawn and never-published destinations intentionally share an unavailable response where anonymous RLS conceals their history.

The configurable gateway expects version-1 JSON over TLS from a fixed allowlisted public IPv4 address with a valid certificate for that address. It sends a small POST containing mode, random request ID and the two points. No coordinates or credentials appear in gateway URLs. Redirects, proxies from the environment, non-HTTPS endpoints, private addresses, credentials in URLs and compression are disallowed. It uses an absolute asynchronous transport deadline and bounded response size, with no automatic retries. Call the private synchronous orchestration in a worker when integrating with an asynchronous server. Contract tests use a disposable local HTTP server and a test-only transport, without real routing or paid services.

Origins must be no older than 30 seconds and within a 250 m synthetic engineering accuracy ceiling. The one-shot private consent capability binds the exact request and recipient. It is separate from browser geolocation permission. Offline calls discard their intent. Stop, revocation, navigation and newer consent invalidate earlier results. The initial transport deadline bounds any in-flight network work. Data already delivered to a third party cannot be recalled. A future approved UI must explicitly connect these events to the session and disclose who receives what data before sending.

Results verify echoed mode, request ID and points, positive finite ETA when supplied, road distance, data age, and up to 1,024 original geometry points. The current protocol requires exact start/end anchoring. It does not infer a road path from straight-line proximity. Geometry-less responses carry only provider-sourced distance and optional ETA. An absent or expired ETA stays unavailable or stale. Unknown traffic is omitted as a guarantee. Results expire by the earliest relevant origin, consent, destination or provider deadline. The optional external map builder requires separately approved HTTPS templates and one-shot confirmation, discloses only the verified destination and reports a prepared handoff rather than successful navigation. No external link or third-party coordinates are wired into the app.

Operational blockers include provider selection and contracts, retention and subprocessors, user-facing disclosure and native-device testing, actual directory and entrance verification, route and ETA accuracy, and representative restricted-role performance. Earlier LOC-02/03 index limitations remain unverified at scale. The plan and acceptance artifacts report synthetic evidence only. Roll back by reverting the service, status text, tests and workflow changes together; no data migration is necessary.
